\chapter{Scenarios}
\label{ch:scenarios}

A scenario is the intended narrative unit in LeanFM. It is a
named, bounded stream of timestamped events that together describe one
interaction or one execution trace of interest (for example: a successful
quote request, an OAuth exchange, or a two-player 9×9 game).

\section{Event envelope and scenario grouping}
Chapter~\ref{ch:events} defines the shared typed event envelope and the semantics
of event identity, \texttt{priorIds}, \texttt{causeId}, actor endpoints,
correlation, and monotonic \texttt{timeAt}. Any serialized \texttt{scenario} key
or aliases such as
\texttt{src}/\texttt{message} must be declared by the accepted schema and its
reducers; they are not additional canonical event fields.

\section{Derived outputs and provenance}
The intended per-scenario views include:
\begin{itemize}
  \item an interaction diagram (lifelines and arrows from message endpoints and kinds),
  \item a residual state machine (observed states and message-labeled transitions),
  \item latency and throughput charts derived from timeAt and prior start/stop pairs,
  \item outcome distributions and other question-specific reductions.
\end{itemize}

A view should carry its originating prompt or requirement id, reducer, unit, and
scenario boundary. Generate it only when those inputs and its renderer are
implemented; do not infer implementation from this target list. When a generated
view can carry the explanation, prefer it to repeated prose and add a short
interpretation (see SKILL.md).

\section{Example: minimal two-player game scenario}
Below is an illustrative event fragment for a 9×9 game. Times are milliseconds
on the model's monotonic clock:
\begin{verbatim}
{ "id":"evt-0010", "priorIds":[], "causeId":null,
  "timeAt":30000, "session":"s-g1", "task":"game-g1",
  "from":"alice","to":"server","kind":"MoveRequested",
  "payload":{"move":"E5","color":"B"} }
{ "id":"evt-0011", "priorIds":["evt-0010"], "causeId":"evt-0010",
  "timeAt":30001, "session":"s-g1", "task":"game-g1",
  "from":"server","to":"alice","kind":"MoveAccepted",
  "payload":{"move":"E5"} }
\end{verbatim}

The latency pair is \texttt{evt-0010} to \texttt{evt-0011}: one millisecond.

Prefer runnable scenario traces to prose-only examples, declare their expected
derived views and provenance, and keep transport mappings in
\texttt{Implementation.lean} after requirements acceptance.
