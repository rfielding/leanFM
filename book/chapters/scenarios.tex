\chapter{Scenarios}
\label{ch:scenarios}

A scenario is LeanFM's named, bounded stream of timestamped events for one
interaction or execution trace (for example, a quote request, OAuth exchange,
or 9×9 game).

\section{Event envelope and scenario grouping}
The shared envelope and semantics of \texttt{id}, \texttt{priorIds},
\texttt{causeId}, actor endpoints, correlation and monotonic \texttt{timeAt}
are defined in Chapter~\ref{ch:events}. A serialized \texttt{scenario} key or
aliases such as \texttt{src}/\texttt{message} are canonical only if the accepted
schema and reducers declare them.

\section{Derived outputs and provenance}
Question-driven outputs include interaction diagrams, residual state machines,
latency/throughput charts and outcome distributions. Each \texttt{DesiredOutput}
must bind its prompt, precise question, event source, reducer, unit and scenario
boundary. A listed output is not implemented until its renderer exists; when a
generated view carries the explanation, prefer it to repeated prose and add a
short interpretation.

\section{Example: minimal two-player game scenario}
Below is an illustrative event fragment for a 9×9 game. Times are milliseconds
on the model's monotonic clock:
\begin{verbatim}
{ "id":"evt-0010", "priorIds":[], "causeId":null,
  "timeAt":30000, "session":"s-g1", "task":"game-g1",
  "from":"alice","to":"server","kind":"MoveRequested",
  "payload":{"move":"E5","color":"B"} }
{ "id":"evt-0011", "priorIds":["evt-0010"], "causeId":"evt-0010",
  "timeAt":30001, "session":"s-g1", "task":"game-g1",
  "from":"server","to":"alice","kind":"MoveAccepted",
  "payload":{"move":"E5"} }
\end{verbatim}

The latency pair is \texttt{evt-0010} to \texttt{evt-0011}: one millisecond.

Prefer runnable scenario traces to prose-only examples, declare their expected
derived views and provenance, and keep transport mappings in
\texttt{Implementation.lean} after requirements acceptance.
