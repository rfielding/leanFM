HTTP is decoded into a grammar-permitted protobuf value, recorded as an
\texttt{EventEnvelope}, and the response or rejection is projected back. Provider
messages stay in-process. Protobuf fixes values and tags; HTTP chooses the browser
representation (today, form-encoded POST bodies and JSON responses, with a secure
session cookie), and the journal stores length-delimited binary envelopes.

\subsection{Conservative default HTTP projection}

Without an explicit binding in \texttt{Implementation.lean}, LeanFM generates an
HTTP projection and its OpenAPI description: an initiating browser-to-server
message is the request, its correlated server-to-browser alternatives are the
responses, and their protobuf schemas the operation schemas. The default is
conservative. Only a field the implementation classifies as a bounded, URL-safe
scalar may go in a path or query; bytes, repeated or nested fields, secrets and
unbounded strings go in a \texttt{POST} body, encoded with the protobuf JSON
mapping as \texttt{application/json}, so a generator cannot leak credentials into
URLs. \texttt{GET /openapi.yaml} publishes the result: method, path, content type,
request schema, every permitted response and status, authentication, correlation
fields and requirement identifier. The protobuf and grammar remain the definitions.

\section{The conversion, field by field}

For a request binding \texttt{httpRequest(method, pathTemplate)}, conversion is
defined in this order:

\begin{enumerate}
  \item Match the HTTP method exactly and split the path into decoded segments.
  \item For each \texttt{\{field\}} in the template, take the protobuf field of
        that name, encode it as one path segment, and reject slashes, traversal,
        or a value that escapes the authenticated project root.
  \item For the currently implemented POST subset, encode remaining browser
        input fields as UTF-8 form values. A protobuf \texttt{bytes} field is
        opaque bytes at the protocol boundary; a form adapter must use an
        explicitly declared textual encoding and must never place credentials
        in a URL, trace, diagnostic, or returned object.
  \item Recover the authenticated user from the
        \texttt{leanfm\_session} HttpOnly, SameSite cookie. The cookie is
        transport authorization, not a field silently added to every protobuf
        message. It authorizes model calls and use of that user's provider
        keys; it does not decide which project may be read, because projects
        are shared.
  \item Validate required fields and task \texttt{where\_} constraints. On
        success, assign the envelope metadata and the oneof payload. On failure,
        emit the named rejection alternative when the grammar has one; otherwise
        return an HTTP error without pretending a successful protocol event
        occurred.
\end{enumerate}

A response binding \texttt{httpResponse(RequestName)} reverses this over the
request's finite response set: scalars become JSON values, repeated fields arrays,
nested messages objects, \texttt{bytes} an explicit download or Base64 field, and
secrets are redacted. Statuses follow convention (200, 201, 400, 401/403, 404,
409, 502), but the named response message, not the status, decides the grammar
transition.

Several exchanges may be in flight, so every response envelope sets
\texttt{cause\_id} to its request's event identifier in the same session and
task, and the adapter follows it to answer on the request's connection, never by
adjacency, arrival order or a global ``current request''. A projection is valid
only for a causally closed exchange: each request named by exactly one terminal
response, a failure being a response too. An orphan request, a causeless or
cross-session response, or two terminal responses fail validation; interim or
streaming responses are modeled explicitly, with one terminal.

\section{Complete LeanFM task grammar}

The whole ChatUI grammar, rendered from its typed values. \texttt{A ! B : Message}
reads ``A sends Message to B''; \texttt{then} sequences; \texttt{choose/or}
alternates; \texttt{optional} allows zero or one; \texttt{fork/join all} waits for
every branch; \texttt{race/join first} takes the first and cancels the rest (unlike
the threshold join of Chapter~\ref{ch:grammar}). A message the current residual
does not admit is illegal even if its bytes decode.

\section{The grammar as an executable canvas}

\textit{Future interface.} The grammar becomes one navigable canvas: a production
closes to its typed boundary or opens to its messages, states, parameters,
constraints, measurements and nested productions, as presentation only. Changing a
typed parameter (a capacity, population, timeout, probability) would mark every
dependent stale and regenerate the affected productions, reducers, proofs, codecs
and views before the revision is committed. A production that crosses HTTP attaches
its binding there (method, path, protobuf types, statuses, content type, codec),
with fixtures that emit and decode the exact bytes, so the canvas opens all the way
down to bytes.

\section{What is checked, and what remains}

Lean elaboration checks actors, schemas, states, transitions, grammars,
constraints, output provenance and mappings; the generator rejects a request with
no named response and incomplete route records; and the repository checks validate
the protobuf against the requirements. Not every accepted route has a handler yet,
and the server does not yet journal every exchange. The accepted grammar is the
contract and the running table the honest conformance statement.
