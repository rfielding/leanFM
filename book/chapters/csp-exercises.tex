\chapter{Protocol Exercises: Roles, Attackers, and Knowledge}
\label{ch:csp-exercises}

\index{CSP}
\index{protocol role}
The author learned from \citet{ryan2001modelling} to treat a security protocol
as communicating roles plus an active intruder, and security as properties of
every trace that intruder can produce. This chapter keeps that idea and none of
that book's examples. Three small invented protocols each press on one part of
the method:

\begin{enumerate}
  \item an \emph{on-call handoff}, where three separately written roles must
        compose into one protocol;
  \item a \emph{sealed-bid auction}, where an attacker who cannot read a bid can
        still copy it; and
  \item \emph{speaker pairing}, where a code shown on a screen is visible to some
        actors and not to others.
\end{enumerate}

Status: the three examples are a design exercise. Their \texttt{RoleSpec},
\texttt{WireTerm} and \texttt{composeRoles} listings are proposed notation, and
there is no role-composition engine yet. The attacker's deduction rules are
implemented (\texttt{LeanFM.Session.Knowledge}), and so is a checker that
generates the attacker from a declaration (\texttt{LeanFM.Session.Attack}),
which Section~\ref{sec:needham-schroeder} uses on a real protocol.

\section{Roles compose by sharing events}

\index{projection}
This is the session-type picture seen from the other side: each role is written
first, as a grammar over its own view of the events, and the global protocol is
whatever their composition admits. Composition synchronizes on shared events; it
does not concatenate scripts. The attacker is the role session types usually
leave out: one that controls the channels and can read, drop, replay or forge
what passes through them, the most hostile physics a channel can declare
(Chapter~\ref{ch:vision}).

\begin{lstlisting}
structure RoleSpec where
  actor    : Actor
  accepts  : Grammar (ProjectedEvent actor)
  initialKnowledge : Knowledge actor

def composeRoles (roles : List RoleSpec) : GlobalGrammar :=
  synchronize roles where
    sendReceiveAgree := sameEventId && sameBytes && oppositeEndpoints
\end{lstlisting}

For a global trace $t$, let $t\!\upharpoonright_a$ keep only the events actor
$a$ sends or receives. The composition accepts a trace exactly when every role
accepts its own view of it:

\AccessibleEquation{The language accepted by compose roles R one through R n equals the set of traces t such that for every i the projection of t onto alphabet a sub i belongs to the language of role R sub i.}{\[
  L(\operatorname{composeRoles}(R_1,\ldots,R_n))
  = \{t \mid \forall i,\; t\!\upharpoonright_{a_i} \in L(R_i)\}.
\]}

A message is one global event with one identity, one byte string, one sender and
one recipient, and both endpoint grammars constrain it. An unmatched send, an
unexpected receive, or disagreement about the bytes empties the composed language
from that prefix on, and the checker reports the prefix. A role may bind values
from events it has seen and test later events against them; the bindings are a
parser environment for the trace, not a claim about implementation memory.

\section{A transport-neutral byte algebra}

\index{bytes}
Security claims need to say which bytes expose which values, without choosing
HTTP, protobuf or a cipher suite. Four symbolic constructors are enough for this
chapter:

\begin{lstlisting}
abbrev Bytes := ByteArray

inductive WireTerm where
  | atom    : Name -> Bytes -> WireTerm
  | tuple   : List WireTerm -> WireTerm
  | encrypt : KeyRef -> WireTerm -> WireTerm
  | hash    : WireTerm -> WireTerm

structure WireEvent where
  timeAt   : ClockTimestamp
  id       : EventId
  priorIds : List EventId
  session  : SessionId
  task     : TaskId
  from     : Actor
  to       : Actor
  channel  : Channel
  term     : WireTerm
  bytes    : Bytes
  encodedBy : bytes = encodeCanonical term
\end{lstlisting}

Anyone may hash a term they know; nobody may invert a hash; decryption needs the
key. \texttt{channel} records who can observe an event at all, which the pairing
example needs. A concrete refinement replaces this idealized algebra with real
transports and cryptography whose assumptions justify it.

\section{Example 1: an on-call handoff}

\index{on-call handoff}
A pager service records who is on call for a team. Exactly one engineer is on
call at any time. Olu is on call and wants to hand off to Ines. The pager must
not move the duty until Ines has actually accepted it, and Olu must learn that
the handoff completed. Each person shares a long-term key with the pager:
$K_O$ for Olu, $K_I$ for Ines.

\begin{enumerate}
  \item Olu $\to$ Pager: $\{\mathit{Ines}, h\}_{K_O}$, with a fresh handoff id $h$.
  \item Pager $\to$ Ines: $\{\mathit{Olu}, h, c\}_{K_I}$, with a fresh challenge $c$.
  \item Ines $\to$ Pager: $\{h, c, \mathit{accept}\}_{K_I}$.
  \item Pager $\to$ Olu: $\{\mathit{Ines}, h, \mathit{done}\}_{K_O}$.
\end{enumerate}

\subsection{Three roles, written separately}

\begin{lstlisting}
def oluRole (olu ines pager : Actor) (ko : SharedKey) : RoleSpec :=
  role olu "outgoing engineer" do
    let h <- fresh Nonce "h"
    from_ olu; to_ pager
    send (encrypt ko.ref (tuple [actor ines, nonce h]))
    from_ pager; to_ olu
    receive (encrypt ko.ref (tuple [actor ines, nonce "h", atom "done"]))
      where_ field "h" == h

def inesRole (olu ines pager : Actor) (ki : SharedKey) : RoleSpec :=
  role ines "incoming engineer" do
    from_ pager; to_ ines
    receive (encrypt ki.ref (tuple [actor olu, nonce "h", nonce "c"]))
    let h <- take Nonce "h"
    let c <- take Nonce "c"
    from_ ines; to_ pager
    send (encrypt ki.ref (tuple [nonce h, nonce c, atom "accept"]))

def pagerRole (olu ines pager : Actor) (ko ki : SharedKey) : RoleSpec :=
  role pager "pager service" do
    from_ olu; to_ pager
    receive (encrypt ko.ref (tuple [actor "next", nonce "h"]))
      where_ field "next" == ines
    let h <- take Nonce "h"
    let c <- fresh Nonce "c"
    from_ pager; to_ ines
    send (encrypt ki.ref (tuple [actor olu, nonce h, nonce c]))
    from_ ines; to_ pager
    receive (encrypt ki.ref (tuple [nonce "h", nonce "c", atom "accept"]))
      where_ field "h" == h && field "c" == c
    from_ pager; to_ olu
    send (encrypt ko.ref (tuple [actor ines, nonce h, atom "done"]))
\end{lstlisting}

The \texttt{where\_} clauses are the context-sensitive part: the message
sequence is context-free, but whether a reply is legal depends on values bound
earlier in the trace.

\subsection{What composition catches}

Suppose a later edit lets the pager send \emph{done} as soon as it has sent the
offer, before Ines replies. Olu's role still accepts that order: Olu never sees
messages 2 and 3. Ines's role still accepts it too. Only the composed protocol
exposes the problem, through the duty properties below:

\AccessibleEquation{It is always true that exactly one engineer is on call.}{\[
  AG\,\mathit{exactlyOneOnCall}.
\]}

\AccessibleEquation{On every future Olu stays on call until Ines has accepted handoff h or Olu stays on call forever.}{\[
  \mathit{onCall}(\mathit{Olu})\ AW\ \mathit{accepted}(\mathit{Ines},h).
\]}

\AccessibleEquation{It is always true that if Olu is told handoff h is done then Ines previously accepted handoff h.}{\[
  AG\bigl(\mathit{toldDone}(\mathit{Olu},h) \rightarrow
    \mathbf{P}\,\mathit{accepted}(\mathit{Ines},h)\bigr).
\]}

The second formula uses weak until on purpose: Ines may never answer, and then
Olu simply remains on call. Strong $AU$ would wrongly demand that every handoff
eventually succeeds. The third is a past claim ($\mathbf{P}$ reads ``previously'').
With the faulty edit, the checker returns a counterexample trace in which Olu
is told \emph{done} with no earlier acceptance, drawn both as the global
interaction diagram and as Olu's local view, in which nothing looks wrong.

The same mechanism catches disagreement about values. If the pager's grammar
could forward the offer to someone other than the engineer Olu named, the
\texttt{where\_ field "next" == ines} guard and Ines's projection cannot both
accept the same event, and the composed language is empty at that prefix.

\section{Example 2: a sealed-bid auction}

\index{sealed-bid auction}
An auctioneer collects bids in two phases. While bidding is open, each bidder
sends a \emph{commitment}: the hash of the amount and a fresh random salt. After
bidding closes, each bidder reveals the amount and salt, and the auctioneer
accepts a reveal only if it hashes to the commitment. The highest revealed bid
wins. Ana and Ben bid honestly. Ivo is also a registered bidder; he is the
attacker, and he sees every message on the network.

\begin{lstlisting}
def bidderRole (b auctioneer : Actor) (amount : Amount) : RoleSpec :=
  role b "bidder" do
    let s <- fresh Nonce "salt"
    from_ b; to_ auctioneer
    send (tuple [actor b, hash (tuple [value amount, nonce s])])   -- commit
    from_ auctioneer; to_ b
    receive (atom "closed")
    from_ b; to_ auctioneer
    send (tuple [actor b, value amount, nonce s])                  -- reveal

def auctioneerRole (auctioneer : Actor) (bidders : List Actor) : RoleSpec :=
  role auctioneer "auctioneer" do
    let commits <- collectWhileOpen fun b =>
      receive (tuple [actor b, ?commitment]) where_ b in bidders
    broadcast (atom "closed")
    forEach commits fun (b, commitment) =>
      receive (tuple [actor b, ?amount, ?salt])
        where_ hash (tuple [amount, salt]) == commitment
    announce (highestRevealed commits)
\end{lstlisting}

\subsection{Secrecy holds, and the auction is still broken}

Before close, Ivo has seen Ana's commitment but cannot invert the hash, so he
does not know her amount. That secrecy property holds:

\AccessibleEquation{On every future Ivo does not know Ana's amount until bidding has closed.}{\[
  \neg\operatorname{knows}(\mathit{Ivo},a_{\mathit{Ana}})\ AU\ \mathit{closed}.
\]}

The auction is still broken. Ivo does not need to know Ana's amount to bid it.
He copies her commitment and sends it under his own name. That is a legal
attacker move: he observed the hash term, and resending a known term is always
derivable. After close he waits for Ana's reveal, which he also observes, and
sends the same amount and salt under his name. The auctioneer's check passes,
because the hash really does match. Ivo has tied Ana's bid without ever having
known it while bidding was open.

The property that fails is about who \emph{formed} each commitment, not about
who knows what:

\AccessibleEquation{It is always true that if the auctioneer accepts a commitment from bidder b then b previously formed that commitment.}{\[
  AG\bigl(\operatorname{acceptsCommit}(\mathit{Auctioneer},b,x) \rightarrow
    \mathbf{P}\,\operatorname{formed}(b,x)\bigr).
\]}

The checker's search for a violation, $EF(\operatorname{acceptsCommit}(\ldots)
\land \neg\mathbf{P}\operatorname{formed}(\ldots))$, returns the copy trace above
as its witness.

\subsection{The fix: bind the bidder into the commitment}

Put the bidder's own name inside the hash:
$\mathit{hash}(b, \mathit{amount}, s)$, and have the auctioneer recompute the
hash with the name of the bidder who sent the reveal. Ivo's copied commitment
was formed with Ana's name. To open it under his own name he would need a salt
that makes $\mathit{hash}(\mathit{Ivo},\ldots)$ equal $\mathit{hash}(\mathit{Ana},\ldots)$,
and no rule derives one. Copying is now useless.

This is the acceptance test for an intruder model: it must find the copy trace
for the original commitment and none for the fixed one. A model that cannot find
the first attack is too weak to trust when it finds nothing in the second.

The symbolic model has a visible limit here. If amounts came from a small set, Ivo
could hash each candidate and compare; the salt stops that. Dolev--Yao deduction
has no notion of guessing, so ``salts are fresh and unguessable'' must be written
down as an assumption.

\section{Knowledge and agreement as theorems}
\label{sec:knowledge-closure}

\index{intruder model}
\index{secrecy}
\index{agreement}
The attacker is one more role. It observes the events its channels let it see,
may block or replay them, and may send any term it can derive from them.

\begin{lstlisting}
inductive Derives : Knowledge -> WireTerm -> Prop where
  | initial : term in knowledge -> Derives knowledge term
  | tuple   : (forall x in xs, Derives knowledge x) ->
              Derives knowledge (.tuple xs)
  | project : Derives knowledge (.tuple xs) -> x in xs ->
              Derives knowledge x
  | encrypt : Derives knowledge key -> Derives knowledge body ->
              Derives knowledge (.encrypt key body)
  | decrypt : Derives knowledge (.encrypt key body) ->
              Derives knowledge (inverse key) -> Derives knowledge body
  | hash    : Derives knowledge x -> Derives knowledge (.hash x)
  -- no rule recovers x from .hash x

def intruderRole (ivo : Actor) : RoleSpec :=
  adversary ivo do
    observe (channelsVisibleTo ivo)
    mayBlock
    mayReplay
    maySend fun knowledge term => Derives knowledge term
\end{lstlisting}

Knowledge is calculated for every actor from every accepted trace, not only the
intended run, so security claims become theorems over accepted traces, derived
knowledge and explicit compromise assumptions. For the fixed auction:

\begin{lstlisting}
theorem auction_bid_sealed_until_close
    (trace : Trace WireEvent)
    (accepted : fixedAuction.Accepts trace)
    (fresh : SaltsFreshAndUnguessable trace) :
    forall b x, beforeClose trace x ->
      not (Derives (knowledgeAt .ivo trace x) (value (amountOf b))) := by
  exact hashHidesSaltedInput accepted fresh

theorem auction_commitments_not_copyable
    (trace : Trace WireEvent)
    (accepted : fixedAuction.Accepts trace) :
    forall b c, acceptsCommit trace b c -> formedBy trace b c := by
  exact boundNameDefeatsCopy accepted
\end{lstlisting}

The two theorems are still proposed notation: the lemmas they name do not
exist yet. The deduction rules do. \texttt{LeanFM.Session.Knowledge} defines
them as \texttt{Derives}, over atoms, symmetric keys, key pairs, pairs,
encryption and hashes; a ciphertext under a private key is a signature, opened
with the public key. It decides them one value at a time: \texttt{analz} takes
what an actor has seen apart until nothing new appears, and \texttt{synth} asks
whether the value can be built from the pieces. (Enumerating everything an actor
could build would never end.) The decision is proved sound:

\begin{lstlisting}
theorem knows_sound {K : List Msg} {v : Msg}
    (h : knows K v = true) : Derives K v
\end{lstlisting}

So when the checker says the attacker knows a value, a derivation exists.
Completeness, that \texttt{knows} misses nothing \texttt{Derives} allows, is
tested on examples but not yet proved, and secrecy verdicts lean on it.

\subsection{Calculated knowledge and policy inside CTL}

Knowledge and policy need not start as new modal operators. Define state
predicates by reducing the event history, then use them inside ordinary CTL.
\texttt{knows} says who can derive a value; \texttt{allows} and
\texttt{requires} say what a declared policy permits and obliges:

\begin{lstlisting}
def knows (actor : Actor) (value : Secret) (s : ProtocolState) : Bool :=
  value in knowledgeClosure actor s.events s.compromise

def allows (policy : Policy) (actor : Actor)
    (action : Action) (s : ProtocolState) : Bool :=
  policy.allows actor action s

def requires (policy : Policy) (actor : Actor)
    (action : Action) (s : ProtocolState) : Bool :=
  policy.requires actor action s
\end{lstlisting}

These functions label a state; CTL says when the labels may or must hold:

\AccessibleEquation{On every future the auctioneer does not know any bid amount until bidding has closed.}{\[
  \neg\operatorname{knows}(\mathit{Auctioneer},a_b)\ AU\ \mathit{closed}.
\]}

\AccessibleEquation{It is possible that the auctioneer eventually knows every revealed amount.}{\[
  EF\,\operatorname{knows}(\mathit{Auctioneer},a_b).
\]}

\AccessibleEquation{It is always true that if an actor knows a handoff challenge then the duty policy allows that actor to possess it.}{\[
  AG\bigl(\operatorname{knows}(x,c) \rightarrow
    \operatorname{allows}(\mathit{DutyPolicy},x,\operatorname{possess}(c))\bigr).
\]}

\AccessibleEquation{It is always true that once the pager moves the duty the duty policy requires it to notify the outgoing engineer and every future eventually records that notification.}{\[
  AG\bigl(\mathit{dutyMoved}(h) \rightarrow
    (\operatorname{requires}(\mathit{DutyPolicy},\mathit{Pager},
      \operatorname{notify}(\mathit{Olu},h)) \land AF\,\mathit{toldDone}(\mathit{Olu},h))\bigr).
\]}

A universal claim is checked by searching for its violation, and the search
result is the useful artifact:

\AccessibleEquation{Every disclosure is always permitted exactly when there is no reachable disclosure that is not permitted.}{\[
 AG(\operatorname{discloses}(a,s) \rightarrow
    \operatorname{allows}(P,a,\operatorname{disclose}(s)))
 \;\equiv\;
 \neg EF(\operatorname{discloses}(a,s) \land
    \neg\operatorname{allows}(P,a,\operatorname{disclose}(s))).
\]}

This state-local \texttt{knows} is not the epistemic modality $K_a\varphi$ over
indistinguishable histories of Chapter~\ref{ch:ctl}. It tests whether one
deduction closure contains a value, which suffices for most secrecy and
authorization claims; $K_a$ is for requirements that compare histories, as the
next example shows.

\section{Example 3: pairing a speaker by a code on its screen}

\index{device pairing}
A new speaker shows a six-digit code $d$ on its own display. Its owner types
the code into a phone, and the phone proves to the speaker that it knows $d$.
The network is hostile; the display is not on the network.

\begin{enumerate}
  \item Speaker $\to$ Owner, on channel \emph{display}: $d$.
  \item Owner $\to$ Phone, on channel \emph{keypad}: $d$.
  \item Phone $\to$ Speaker, on channel \emph{network}: $p,\ \mathit{hash}(p, d, \mathit{Phone})$, with a fresh nonce $p$.
  \item Speaker $\to$ Phone, on channel \emph{network}: \emph{paired} or \emph{rejected}.
\end{enumerate}

\begin{lstlisting}
receive (tuple [nonce "p", ?proof]) on network
  where_ sender != speaker
  where_ proof == hash (tuple [nonce p, value shownCode, actor sender])
  where_ failedAttempts < 3
\end{lstlisting}

Three things are new compared with the first two examples.

\paragraph{Channels decide what each actor observes.} The display and keypad
events belong to the observations of the speaker, the owner and the phone, not
to Ivo's. That is what keeps $d$ out of Ivo's knowledge closure, and it is a
modeling assumption about the room, so it is stated as one. Remove it and the
checker should immediately find Ivo pairing his own phone.

\paragraph{A counter is context, too.} \texttt{failedAttempts < 3} depends on
how many earlier proofs failed in this trace. Like the equality guards, it
keeps the grammar context-free and moves the counting into a named predicate.

\paragraph{Guessing is a probability, not a deduction.} Ivo cannot derive $d$,
but he can guess it. The symbolic model says $EF\,\mathit{paired}(\mathit{Ivo})$
is true: some future has a lucky guess. That verdict is correct and useless on
its own. The requirement is a bound on how likely that future is, carried by a
probability overlay: with three attempts against $10^6$ codes,

\AccessibleEquation{The probability that Ivo eventually pairs is at most three in one million.}{\[
  P[F\,\mathit{paired}(\mathit{Ivo})] \le 3/10^6.
\]}

The next section explains why the number attaches to $E$.

\paragraph{Some claims compare histories.} ``Ivo cannot tell which code was
shown'' is not true or false of one state: it says any two histories differing
only in $d$ look identical to Ivo. That is $K_a$ over indistinguishable
histories, a relational theorem rather than a CTL state formula, and the one
claim in this chapter that the table below does not cover.

\section{Where each modality attaches}

\index{probability overlay}
\index{deadline}
\index{modality}
The examples have used every kind of claim a requirement needs: what can or must
happen, how likely, by when, who knows, who may, and who must. None needs a new
logic. A CTL operator is a path quantifier, $A$ or $E$, fused with a temporal
operator such as $F$, $G$ or $U$: probability belongs to the quantifier, deadlines
to the temporal operator, and knowledge and policy are predicates on states.

\paragraph{The path quantifier $E$ invites ``how likely?''} $E$ says that
\emph{some} future satisfies the path formula; the refinement replaces ``some''
with a probability over futures, whatever follows the $E$:

\AccessibleEquation{E F p becomes the probability of F p. E G p becomes the probability of G p. p E U q becomes the probability of p U q.}{\[
  EF\,p \;\leadsto\; P[F\,p],\qquad
  EG\,p \;\leadsto\; P[G\,p],\qquad
  p\ EU\ q \;\leadsto\; P[p\ U\ q].
\]}

The number comes from an overlay of branch probabilities, as in the bakery
chapter, and is reported beside the CTL verdict, never in place of it. The
overlay cannot make $EF\,p$ false: a future with probability $3/10^6$ is still
possible, and so still needs the handling that possibility demands. Nor does
$A$ become ``probability one'': a set of futures can have probability one and
still leave out a future that $A$ must cover, which is why
Chapter~\ref{ch:ctl} keeps $A$ and $E$ about legal futures only.

\paragraph{The temporal operator $F$ invites ``by when?''} $F$ has no bound, and a
user waiting on a handoff needs one, so the deadline is written on $F$ (and on
the right of $U$): $AF_{\le t}\,q$ says every future reaches $q$ within $t$,
$EF_{\le t}\,q$ that some future does. A deadline under $A$ is a promise the
grammar must keep: every waiting state needs a timeout branch ending in an
explicit outcome, or some future waits past $t$.

\AccessibleEquation{On every future within fifteen minutes handoff h is either accepted by Ines or has expired.}{\[
  AF_{\le 15\,\mathrm{min}}\bigl(\mathit{accepted}(\mathit{Ines},h) \lor \mathit{expired}(h)\bigr).
\]}

\AccessibleEquation{It is always true that once bidding has closed on every future within the reveal window each bidder has either revealed or forfeited.}{\[
  AG\Bigl(\mathit{closed} \rightarrow
    AF_{\le T_{\mathit{reveal}}}\bigl(\mathit{revealed}(b) \lor \mathit{forfeited}(b)\bigr)\Bigr).
\]}

So the handoff needs an \emph{Expired} message to both engineers when the offer
times out, and the auction a \emph{Forfeited} outcome for a bidder who never
reveals: new legal branches, with decodable messages and code that handles them.

\paragraph{The two annotations compose.} Probability on the quantifier and a
deadline on $F$ combine into the question stakeholders usually ask: how likely
is it to happen in time? An owner pairing a speaker within a minute is

\AccessibleEquation{The probability that the phone is paired within sixty seconds.}{\[
  P[F_{\le 60\,\mathrm{s}}\,\mathit{paired}(\mathit{Phone})],
\]}

which a measured overlay reports from real pairing attempts. Keep a guaranteed
deadline ($AF_{\le t}$, enforced by a timeout branch) separate from a usual one
($P[F_{\le t}]$, measured). The bakery chapter shows why: a declared delay
promised a 1.2\,s sale while only about half the recorded sales met it.

\paragraph{\texttt{knows}, \texttt{allows} and \texttt{requires} complete the
set.} These are about actors rather than futures, and each is computed from the
history up to a state, so the temporal operators carry them unchanged. Secrecy is
\texttt{knows} under $AU$; authorization is \texttt{knows} implying
\texttt{allows} under $AG$; an obligation is \texttt{requires} paired with
$AF_{\le t}$ on the act that discharges it.

\section{Needham--Schroeder, checked}
\label{sec:needham-schroeder}

\index{Needham--Schroeder}
\index{Lowe's attack}
The public-key protocol of Needham and Schroeder (1978) has three messages:

\input{generated/ns-protocol.tex}

Alice runs it once, with a peer she chooses: Bob, or Ivo. Bob answers once,
whoever claims to be calling. Ivo is a legitimate user with his own key pair, so
Alice may well choose him; he is also the network, seeing every message and
sending anything he can derive.

Nobody builds the state space. Each honest role is a short script over message
patterns: a choice, sends, receives and claims; a variable in a received pattern
binds whatever the message carries there.

\input{generated/ns-roles.tex}

\texttt{LeanFM.Session.Attack} generates the model. Every message an honest role
sends goes to the network, which is Ivo; every message it receives is one Ivo can
build in the expected shape. That is the Dolev--Yao channel, declared once rather
than written into each role. A state is each role's position and bindings, Ivo's
knowledge (kept taken apart, so \texttt{knows} is an ordinary label), and the
claims made so far.

Requirements become flags that events trip. \texttt{SecrecyBreach} trips when Bob
has committed to Alice and Ivo can derive Bob's nonce; \texttt{Impersonation}
when Bob has committed to Alice although Alice never claimed to be running with
Bob. \texttt{check\_ctl} decides \texttt{never} of each, and that an honest run
can complete. The last row asks secrecy with \texttt{knows} and \texttt{claimed}
atoms instead of a flag and gets the same verdicts. The same declaration, as JSON,
is what the MCP tool \texttt{check\_protocol} takes:

\end{center}

For the 1978 protocol the counterexample is the attack Lowe found in 1995, in the
checker's own words:

Alice talks to Ivo, as she meant to. Ivo re-encrypts her first message for Bob,
who answers ``Alice'' with his nonce under Alice's key. Ivo cannot read that
answer, but he does not need to: he forwards it, and Alice, who believes it is
Ivo's reply, decrypts it and sends Bob's nonce back to Ivo under Ivo's key. Ivo
now knows the nonce, and returns it to Bob, who finishes believing he talked to
Alice. Lowe's fix adds Bob's name to the second message, and Alice checks it is
the peer she chose. With it both properties hold on every reachable state.

The model is bounded, and the bounds are where attacks could still hide: each
session runs once, and a variable binds a name or nonce from a declared domain,
never a whole ciphertext, so Ivo forwarding a sealed blob he cannot read is out
of reach. Lowe's attack needs one session of each role; an attack needing a
second run of Bob needs a second session, which a declaration can ask for.

\subsection{A defender on the wire}

\subsection{Marking secrets}
\label{sec:secrets}

\index{secrets}
Computing everything an attacker could derive is the expensive part of these
checks, and most of it answers questions nobody asked. Ivo learning Alice's name
matters to no one. So a declaration marks what must stay secret, and the mark is
the question: \emph{the attacker never derives this, on any path}. That is
\texttt{AG not knows(Ivo, s)}, decided once for each marked secret.

There are two ways to mark a secret. A name ending in \texttt{\_secr} marks an
atom or key by name: \texttt{passwd\_secr}, or a fresh \texttt{na\_secr}, whose
copies in later sessions are secrets too. Any other term, compound ones included,
is listed in \texttt{secrets}. The distinction matters for hashes. A hash hides
its input, so \texttt{h(passwd\_secr)} reveals nothing about the password, and
the hash is not secret merely because its input is. But a server that accepts
the hash in place of the password has made the hash a password. It must be
marked, and listing \texttt{\{hash: \{atom: passwd\_secr\}\}} does that.

In clear, the password stays secret and the hash leaks, which is exactly the

The last line is a warning from a one-line declaration that sends a

reported rather than silently left unchecked, because a forgotten marker would
otherwise look exactly like a pass.

The idea is close to Perl's taint mode, from the other side. Taint protects
\emph{integrity}: data from outside is marked, the mark follows it, and it may
not reach a sensitive operation unchecked. A secret mark protects
\emph{confidentiality}: the marked data may not reach the attacker. Both are
labels that follow data, and both need a rule for when the label stops: Perl's
is matching the data against a pattern, ours is a one-way function, and in both
cases the rule is wrong exactly when the result is itself a credential.

A mark asks an unconditional question. In Needham--Schroeder with
\texttt{nb\_secr} marked, the nonce leaks even with Lowe's fix, because Bob may
legitimately run with Ivo and tell him. Secrecy that depends on whom a role
talks to stays a formula, like \texttt{never (claimed commit(B, A) and
knows(Ivo, nb))} above. The marks are for values that must never leave, whoever
asks: passwords, private keys, the hash a server accepts.

\subsection{Reassembly}
\label{sec:reassembly}

Signature matching has a subtler gap. A defender scanning a TCP stream for
\texttt{EVIL} must reassemble it as the host behind it will, and the attacker
controls segmentation: any byte range, in any order, repeated with different
bytes. Where segments overlap, one implementation keeps the first bytes and
another the last, and operating systems have differed in exactly this.
\texttt{check\_reassembly} models each stream position as empty, the signature's
byte, or another byte (written \texttt{.}), applies every segment to the
defender's and the host's copies with their own policies, and resets the stream
when a blocking defender matches. The search covers every segmentation:

\end{center}

When the policies differ, two segments are enough: a first-wins defender fed a
decoy byte at offset 0 and then the whole signature keeps the decoy and sees
\texttt{.VIL}, while a last-wins host sees \texttt{EVIL}. When they agree, no
segmentation separates the copies. The same disagreement makes a host
fingerprintable: send overlapping segments and see which bytes it acts on. The fix,
as later intrusion-prevention systems did, is to normalize: the defender forwards
the bytes it scanned, leaving the host no overlap to resolve differently.

\section{What these exercises demand from the library}

The three examples produce a concrete checklist:

\begin{enumerate}
  \item actor-local grammar definitions and trace projection;
  \item synchronization by common event identity and bytes;
  \item typed symbolic variables and prefix-dependent guards, including
        equalities and counters;
  \item a transport-neutral term-to-byte relation with encryption and hashing;
  \item channels, so that each actor's observations are declared;
  \item explicit initial knowledge, compromise and freshness assumptions;
  \item attacker closure under construction, decryption and hashing (done:
        \texttt{LeanFM.Session.Knowledge}, decision proved sound), and an
        attacker generated from role declarations (done:
        \texttt{LeanFM.Session.Attack});
  \item past operators for agreement claims such as
        ``accepted only if previously formed'';
  \item probabilities on the $E$ quantifier, from overlays, reported next to
        CTL verdicts;
  \item deadlines on $F$ and $U$, with timeout branches wherever $A$ must
        meet them;
  \item relational theorem schemas for indistinguishability; and
  \item counterexamples drawn both as a global interaction diagram and as each
        actor's local projection.
\end{enumerate}

None of this is security decoration. It tests whether separately written,
context-sensitive role grammars stay modular while still expressing the
information flow that real behavioural claims depend on.
