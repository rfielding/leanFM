\chapter{Session Histories Made of Events}
\label{ch:events}

\index{event}
\index{trace}
\index{session type!run of}
A global type says which conversations are legal. An \emph{event} is one message
of one actual session, recorded as it happened; checking an implementation means
checking its list of events against the global type and its physics. A small
common envelope makes histories comparable across protocols:

\begin{lstlisting}
structure Event (Actor Session Task Kind Payload : Type) where
  timeAt  : ClockTimestamp
  id      : String
  priorIds : List String
  causeId : Option String
  session : Session
  task    : Task
  from    : Actor
  to      : Actor
  kind    : Kind
  payload : Payload

abbrev Trace (Actor Session Task Kind Payload : Type) :=
  List (Event Actor Session Task Kind Payload)
\end{lstlisting}

\texttt{id} identifies a visible fact. \texttt{priorIds} lists immediate
predecessors, and \texttt{causeId} optionally names the one event that directly
caused this one (MCP's \texttt{check\_trace} spells them \texttt{prevIds} and
\texttt{causeIds}, protobuf \texttt{prior\_ids} and \texttt{cause\_id}).
\texttt{from} and \texttt{to} are the roles; \texttt{session} names the instance
of the global type, and \texttt{(session, task)} correlates independently
progressing conversations; \texttt{kind} is a stable discriminator; the payload
carries the parameters that flow between productions. \texttt{timeAt} comes from
a shared monotonic clock whose differences measure elapsed time; its origin does
not matter.

Predecessor links form a directed acyclic graph. A fork is several events naming
the same predecessor; a join is one event naming every branch it depends on. An
end event may also name its start, which makes elapsed time
\texttt{end.timeAt - start.timeAt} even when attempts with the same
\texttt{(session, task)} overlap; such an edge may be redundant for ordering but is
useful correlation. A predecessor edge means ``ordered after'', not ``caused by''.

\texttt{causeId} is the causal pointer, and it adds or removes no interleavings. A
task start may cause messages, which may cause nested task starts, and a terminal
points to the event whose work it finishes. The reverse relation gives causal
subtrees, which a renderer draws as nested labeled boxes without pretending that
concurrent children are ordered. The pointer also makes choices checkable: a role
decides only from its own history, so \texttt{causeId} must name an event its
sender sent or received (Chapter~\ref{ch:vision}). A response's \texttt{causeId}
is its request's \texttt{id}, which stays unambiguous with many requests in flight
because it follows identity, not adjacency.

An $m$-of-$n$ join also records $m$, $n$ and the $m$ distinct branch-terminal IDs,
members of \texttt{priorIds}, that satisfied it; two predecessors alone cannot
distinguish two-of-three from an ordinary two-branch join.

Two events are concurrent when neither is an ancestor of the other:

\begin{lstlisting}
def concurrent (events : List AnalysisEvent) (a b : EventId) : Bool :=
  !reachable events a b && !reachable events b a
\end{lstlisting}

The trace's maximum concurrency is the partial order's width, its largest
antichain; this purchase is a chain, of width one. Incomparable events may appear
in either order in a serialization. Runtime concurrency, unlike order width, needs
separate start and completion events. In the next trace a request forks into two
task attempts whose completions point back to their starts and are joined by the
response; the shading is grouping only.

edgeTime(prior, event) := event.timeAt - prior.timeAt

Knowledge is another reduction: the actors that can derive a value from their
initial knowledge and the bytes they see.

\begin{lstlisting}
def knowers (actors : List Actor) (v : ValueRef)
    (events : List AnalysisEvent) : List Actor :=
  actors.filter fun actor =>
    Derives (knowledgeFrom actor events) v
\end{lstlisting}

``Only these actors know $v$'' compares that set with an allowed one; secrecy is
not a separate primitive (Section~\ref{sec:knowledge-closure}).

\section{Derived state}

A current session, an authenticated principal or an outstanding request is
computed by folding the trace, so its evidence stays visible. Private state enters
the model only when two executions with the same visible trace may legally diverge,
and even then the first remedy is to expose the distinction as an event or
parameter.

\section{Time is more than a timestamp}

\index{time}
Timing constraints pair explicit boundaries; changing a timeout changes the
requirement, not the order or causal relations. Elapsed time between two events of
one \texttt{(session, task)}:

\begin{lstlisting}
def elapsed (start finish : Event) : Option Duration :=
  if start.session = finish.session &&
     start.task = finish.task &&
     start.timeAt <= finish.timeAt
  then some (finish.timeAt - start.timeAt)
  else none
\end{lstlisting}

Latency queries name their boundary kinds and select the start through the
terminal's backpointer, since \texttt{(session, task)} alone cannot separate
overlapping attempts; reducers never pair by adjacency. Every declared terminal
uses the same pairing. A collapsed production keeps its boundary IDs, links,
parameters, aggregate deltas and validation status, so opening and closing it
changes presentation only.

\section{Estimating completion from an event stream}

\texttt{LeanFM.StreamStats} reconstructs attempts from observed terminal-to-start
links. For a window with $M$ starts, $C$ matched terminals, $S$ successes and
completed latencies $L_1,\ldots,L_C$:
\AccessibleEquation{Estimated completion probability equals completed count C divided by started count M. Estimated probability of success given completion equals success count S divided by completed count C. Estimated expected latency given completion equals the sum of completed latencies L sub i divided by C.}{\[
  \widehat P(\text{complete}) = \frac{C}{M}, \qquad
  \widehat P(\text{success}\mid\text{complete}) = \frac{S}{C}, \qquad
  \widehat E[L\mid\text{complete}] = \frac{\sum_i L_i}{C}.
\]}

Attempts without a terminal are \emph{in flight}: they count as started and load
the queues, but are not failures, which would bias both estimates whenever the
window closes first. The statistics group by task, actor, time bucket, concurrency
or queue occupancy. Specified probabilities and dwell are predictions; these are
measurements to compare with them.

\section{Charts as declarative trace reductions}

\index{chart specification}
A proposed chart declaration (illustrative, not implemented) names an event
source, a grouping or \(x\) expression, and an aggregate or \(y\) expression: a
reduction, not rendering code.

\begin{lstlisting}
def outcomeShare : ChartSpec :=
  pie "quote outcomes" do
    source events
    where_ (kind == "quote accepted" || kind == "quote declined")
    groupBy kind
    value count

def responseLatency : ChartSpec :=
  line "quote response latency" do
    source (correlate events by "quoteId")
    x clock
    y (elapsed "quote offered" "customer decision")
    series "p50" median

def latencyByConcurrency : ChartSpec :=
  xyplot "latency by concurrent sessions" do
    source completedRuns
    x maxConcurrentSessions
    y (mean (elapsed firstEvent terminalEvent))

def queueByOfferedLoad : ChartSpec :=
  xyplot "queue occupancy by offered load" do
    source completedRuns
    x requestsPerSecond
    y (mean totalQueueOccupancy)

def propagatedGrantProbability : ChartSpec :=
  xyplot "user probability propagated through deterministic servers" do
    source parameterSweep
    x userGrantProbability
    y terminalGrantProbability
\end{lstlisting}

An XY plot has two numeric axes; a time series's \(x\) is the event clock, a
categorical chart's are labels. The last example sweeps a parameter to check that
deterministic processing transports the user's probability mass. Each generated
chart follows the provenance rule of Chapter~\ref{ch:scenarios}.

\section{Round trip through bytes}

A generated scenario must cross the byte boundary both ways.
\texttt{ScenarioEvent} in \texttt{Requirements.proto} carries identity, the
\texttt{prior} list, correlation key, actors, \texttt{timeAt} and the payload
atom. The round-trip check decodes the bytes, compares the value with the generated
one, and checks the reconstructed \texttt{prior} graph; losing a fork or join
fails the build.
