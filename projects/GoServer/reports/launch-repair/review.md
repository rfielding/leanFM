# Local launch repair

User request: make run from source/ launches the app on a port separate from
LeanFM, with the shortest conversation to running software and durable inputs
for later specification refinement and PRs.

The generated inspection launcher already existed. It bound all interfaces on
LeanFM's 8080 and sent snake-case JSON fields to untagged Go structs, so browser
requests did not authenticate or reach the intended core operation. Repair
retains its endpoints/page and the accepted in-process core mapping, uses
127.0.0.1:8081, supports make run PORT=8090 and leaves occupied listeners alone.
Explicit JSON tags and matching browser fields now exercise rooms, games and
chat. HTTP tests verify these actual payloads rather than only source existence.

Positive invariant: the local inspection app starts independently and reaches
authorized, correlated room/game/chat operations. Negative controls reject the
LeanFM port (including alternate numeric spelling), foreign Host/Origin,
non-POST API calls, unknown fields, multiple/truncated/oversized or invalid
UTF-8 bodies. Responses use textContent in the page and restrictive headers.
Requests and core session/room/game/replay admission are finite. Session tokens
use OS randomness; a new local demo session cannot claim an existing identity.
The application remains an in-memory local inspection slice, with no provider
keys or production account registration.

The real runtime check launches make run in an isolated filesystem/process/
network worker, probes readiness and the page, rejects bind-all/extra listeners,
and stops its own child group. Evidence is tied to exact source/specification
hashes and cannot be written by model workspace tools. Go core/HTTP race tests
and runtime checks provide bounded evidence, not a semantic proof.

Earlier audit findings remain explicit: protobuf byte codecs/round-trip proof,
traceability completeness and the accepted blocking-channel counterexample
still require follow-up. No claim of a complete Go gameplay clone or full
refinement is made. Original generated bytes are retained as .txt snapshots
below before/ so a parent Go module cannot mistake them for live packages.

The source now has its own repository boundary. The book, canonical typed
specifications, gate snapshots, goal/launch memory and verification reports
are sufficient for a fresh engineering session or PR review after chat deletion.
No conversation, credential vault, session work record or build cache belongs
in a source commit. No project remote has been invented or published.
